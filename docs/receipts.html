The thanks trap
"Thanks" keeps the line no tool on the acknowledgement "Next" fires tell_joke
Down an 8 kHz line, "next" and "thanks" are nearly the same word, and the costs are asymmetric: a wrong "next" costs one joke, a wrong "thanks" costs the whole call. So thanks never hangs up, the acknowledgement gets a beat and a door, and the run continues.
Gate: acknowledgement vs plain words of leaving. The suite's acknowledgement probes assert that "thanks" never ends a call; a regression goes red before it reaches a caller.

Reads the calendar. "What's on my calendar this week?" routes to get_calendar and reads days and times back. Private event names are silenced and the redacted track re-transcribed to prove none survive.
Gate: calendar routing. Suite probes, disfluencies kept, hold this utterance-to-tool mapping.
calculate
Arithmetic is offloaded, never guessed. "Split 87.50 three ways with a 20% tip" goes to the calculate tool, so the number is computed, not hallucinated.
Gate: arithmetic offload. The suite asserts calculate fires, so no spoken number is ever a guess.

Live data, not stale memory. "What's the weather this weekend?" hits get_weather (straight to open-meteo, no server hop) and speaks a real forecast.
Gate: live data over recall. Probes assert the forecast comes from get_weather, never from memory.

Gate: travel routing. One utterance must reach one get_distance call; the suite holds that mapping.

WATCHED IN PRODUCTION
After the suite passes, the dashboard takes over
The suite gates changes; a live dashboard watches the shipped agent. Metrics, alerting, and model governance: every production call feeds three panels, refreshed by cron with no human in the loop, and harness traffic is excluded so the instrument never grades itself.
reliability
Responsiveness, as a human hears it. Answer latency measured from the end of caller speech: 1.6s median, p95 10.8s. Tool latency 1.6s, dead-air 0.4 per call, 1% tool failures of 81 lookups, and a 100% clean-close rate. The slowest tool is named, not averaged away. Each metric alarms at a stated threshold; the SLO table in the repo README carries the targets.
usage
Conversation quality. Friction (the caller correcting the agent) at 0%, interruptions 0.5 per call, 9.1 turns and 43 seconds per call across 39 production calls in three days, with the tool mix tracked per conversation.
governance
Model governance. The fallback order is pinned, not the vendor default, and the dashboard counts how often the backup brain actually fired (17% of conversations). Every billed model is checked against an allowlist (rogue models: none), and LLM credit burn is compared to the pinned baseline, currently flagged at 1.82x.
watchdogs
Unattended process. A bridge watchdog every 30 minutes, a metrics sweep every 6 hours, and a daily model watch: credit burn and days left, allowlist membership, and goodbyes that did not hang up. Alerts page loudly; silence is never treated as evidence.
Redaction, verified by machine: where a call touches real life (call 01), the sensitive spans are silenced and the redacted track is re-transcribed to prove none of the original names survive. Where an ASR imagines words over the silence, that is the transcriber hallucinating, not the audio.

Voices: the caller is a synthesized clone of the owner's voice, played over the line by the test harness; AJ's voice is a designed persona voice. Neither is a recording of a natural person speaking these words live.
